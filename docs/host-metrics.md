# 底栏资源

设置 → 终端底部状态栏：上组对应底栏左侧，下组对应右侧，中间保留空隙。勾选显示，拖动手柄可在组内排序，或拖到另一组的项目、标题切换位置（松开即保存）；空组仍可接收拖放。默认左侧依次显示系统、CPU、CPU 温度、内存、磁盘容量、下载、上传；右侧显示终端行列与分屏。磁盘读写、运行时间以及右侧的 SSH RTT 与 tmux RTT 默认关闭。
配置是客户端 `workspace.json` 中的一份有序列表，各主机共用；不记录采样历史。
不支持或无法读取的可选资源指标自动隐藏。所有资源项关闭时停止资源采集；RTT 独立采样，仅启用相应项且远端终端状态栏可见时运行。
底栏没有点击弹窗，每项悬浮显示自己的详情。

## 采集

- 当前主机保持一个采集任务，脚本循环采样后等待 5 秒。只采集启用项对应的动态指标组（上传、下载共享网络计数）；调整显示顺序不会重启采集，调整启用项会重新启动采集脚本。
- 系统名称、CPU 型号等静态信息首次读取后复用。磁盘容量每 6 轮更新一次（至少约 30 秒），中间复用上次结果；CPU、内存、网络速率、磁盘读写和温度仍按每轮更新。
- Linux 用 `sh` 读取 `/proc`、`/sys`、`df`；Windows 用系统 PowerShell/CIM 和网络 cmdlet。
- 本机运行隐藏的子进程。切换主机、关闭监控或退出时终止本机子进程或关闭远端 channel。
- SSH 首次探测 `uname -s`，识别 Linux；Windows 使用 PowerShell。探测是短 channel，成功后的采集使用一个辅助连接上的常驻 channel。
- 两端都经标准输入接收固定脚本，不上传文件、不需要 Python。Windows 仅编码短启动命令，避免 cmd 的命令长度限制。
- 失败后间隔 30 秒重试，连续失败 3 次停止采集；成功采样清零失败次数。切换主机或关闭再开启监控可重新采集。读超时 45 秒，给首次 CIM 查询留出时间。首次速率等待第二次采样。
- 速率按远端采样时钟差计算，计数回退、设备消失或重连不会产生负数或尖峰。

## 口径和边界

- 网络底栏展示默认出口；详情逐网卡展示，不合计虚拟网卡、桥接网卡和物理网卡。累计值不是每日流量。
- Linux 默认 IPv4 出口优先，IPv6 作为回退；策略路由、VPN 分流和多个默认出口不等于整机流量总计。
- 磁盘容量是系统分区；悬浮列出本地挂载点。磁盘 IO 底栏合计整个磁盘的读写速率，悬浮展示参与合计的磁盘列表。Linux 选取 /sys/block 中无 slaves 的整盘，排除 loop/ram/zram；Windows 使用 PhysicalDisk，排除 _Total。分区和叠加层不重复累计。
- Windows 分页文件与 Linux 交换空间统一放在内存悬浮详情；负载指标已移除，旧配置中的 load 项自动忽略。Windows 不伪造温度。
- Windows 内存使用总物理内存减可用物理内存；Linux 使用 MemTotal − MemAvailable。
- CPU 总量和各核心均使用两次计数差；Windows 原始 PercentProcessorTime 是 idle 计数，与 Timestamp_Sys100NS 组合计算。
- macOS/BSD 尚未实现采集。Windows 本机和 Linux SSH 有真实采集测试；Windows SSH 尚需目标服务器端到端验证。

底栏系统项显示发行版名；其他系统信息仅悬浮显示。内存直接显示占用；CPU 悬浮只列各核心，磁盘悬浮只列容量。温度优先 CPU 封装/Tdie，然后 Tctl/CPU 核心；同优先级取最高值，没有 CPU 传感器则隐藏。

温度悬浮使用中文分类，只展示处理器、可识别的显卡和硬盘。多个同类传感器取最高读数并标注；未知传感器、重复的 CPU 核心条目隐藏。自定义顺序保留，可通过“恢复默认”应用新顺序。
